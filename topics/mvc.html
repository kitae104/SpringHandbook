MVC

Model, View, Controller로 책임을 나누는 구조이며 Spring MVC는 웹 요청 처리의 핵심 기반입니다.

왜 배워야 할까

MVC는 요청 처리 코드를 한 클래스에 몰아넣지 않기 위한 기본 구조입니다. Controller는 요청을 해석하고, Model은 데이터를 담고, View는 화면을 담당합니다.

REST API 프로젝트에서는 View 템플릿 대신 JSON 응답을 반환하는 경우가 많습니다. 그래도 Spring MVC의 요청 매핑, 파라미터 바인딩, 검증, 예외 처리 흐름은 그대로 사용됩니다.

관련 어노테이션과 기술

@Controller

View 이름을 반환하는 전통적인 MVC Controller입니다.

@RestController

@Controller와 @ResponseBody를 합친 API용 Controller입니다.

@ModelAttribute

쿼리 파라미터나 form 데이터를 객체로 바인딩합니다.

함께 확인하거나 수정할 부분

templates 디렉터리

Thymeleaf 같은 서버 렌더링 화면을 사용할 때 확인합니다.

static 디렉터리

정적 CSS, JS, 이미지 파일을 둘 때 사용합니다.

Controller 테스트

@WebMvcTest로 MVC 계층만 가볍게 테스트할 수 있습니다.

API에서의 Spring MVC

@RestController
class CourseController {
    @GetMapping("/api/courses")
    List<CourseResponse> courses() {
        return courseService.findAll();
    }
}

처리할 때 주의할 점

  • Controller가 비즈니스 규칙을 직접 처리하기 시작하면 Service 분리를 검토합니다.
  • View 기반 MVC와 REST API MVC의 응답 방식 차이를 구분합니다.
