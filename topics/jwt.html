JWT ★★★

로그인 결과를 서명된 토큰으로 표현해 클라이언트가 요청마다 인증 정보를 전달하는 방식입니다.

왜 배워야 할까

JWT는 JSON Web Token의 줄임말입니다. 서버가 로그인 성공 시 토큰을 발급하고, 클라이언트는 Authorization 헤더에 Bearer 토큰을 담아 API를 호출합니다.

JWT는 서버 확장에 유리하지만 토큰 탈취, 만료, 재발급, 로그아웃 처리가 중요합니다. Access Token과 Refresh Token을 분리해 설계하는 경우가 많습니다.

관련 어노테이션과 기술

OncePerRequestFilter

요청마다 한 번 실행되는 JWT 인증 필터를 만들 때 자주 상속합니다.

@AuthenticationPrincipal

JWT 검증 후 만들어진 인증 사용자 정보를 받습니다.

함께 확인하거나 수정할 부분

SecurityConfig

세션을 STATELESS로 두고 JWT 필터를 Security 필터 체인에 추가합니다.

application.yml

JWT secret, access-token-expiration 같은 값을 환경 변수 기반으로 관리합니다.

CORS

Authorization 헤더를 프론트엔드에서 보낼 수 있게 허용합니다.

Authorization 헤더에서 토큰 읽기

String header = request.getHeader(HttpHeaders.AUTHORIZATION);
if (header != null && header.startsWith("Bearer ")) {
    String token = header.substring(7);
    Authentication authentication = jwtProvider.getAuthentication(token);
    SecurityContextHolder.getContext().setAuthentication(authentication);
}

처리할 때 주의할 점

  • JWT payload는 암호화가 아니라 인코딩에 가깝기 때문에 민감 정보를 넣지 않습니다.
  • 토큰 만료 시간을 너무 길게 잡으면 탈취 시 피해가 커집니다.
